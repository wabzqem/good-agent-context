# Expanded-memory sequential pilot

This follow-up uses the same pinned [`antfu-collective/ni`](https://github.com/antfu-collective/ni) snapshot as the first pilot, but expands the repository memory corpus to at least 60 verified entries. It then measures two related coding tasks in sequence, with a fresh agent session for each task and a persistent worktree per arm.

The sequence is layered `.nirc` discovery ([task #362](task-362-sequence.md)), followed by a warning for a missing explicit config file ([task #368](task-368-sequence.md)). Both task prompts are identical across arms. They direct an agent with GAC access to omit `scope_id`, letting the checkout config select the repository scope; this removes the invalid-capability-call confound observed in the first pilot. The prompts also disallow reading external skill files.

The two arms start from the same pinned commit with identical dependencies and `.good-agent-context.yaml`. Each task-1 agent edits its own worktree. After independent grading, its changed implementation, tests, and documentation are committed locally in that eval worktree. Task 2 starts in a fresh Codex session in the same arm's worktree, so it sees task 1's code but not its conversation. The GAC arm additionally receives a verified, post-commit memory update that supersedes the now-stale config-caching memory; baseline receives no cross-session summary. This is the intended long-term-memory treatment.

Grade task 1 with `heldout-362.spec.ts`. Grade task 2 with `heldout-368.spec.ts` and rerun the task-1 held-out check as a regression. Record correctness, total and uncached input tokens, output tokens, elapsed time, tool calls, and shell commands for each run and cumulatively. Count memory seeding and update costs separately. These are still single attempts, so differences are descriptive rather than statistically conclusive. Because each arm carries forward its own patch, task-2 performance reflects the full workflow, including any differences in task-1 code quality; it does not isolate memory retrieval alone.
