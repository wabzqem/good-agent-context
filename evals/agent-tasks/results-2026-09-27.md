# Pilot results — 2026-09-27

See [the protocol](README.md) for the pinned inputs and procedure. Both arms implemented both tasks and passed the independent held-out checks. The results do **not** show a consistent efficiency win for GAC: it was slower and used more tokens on the script-picker task, but faster and used fewer total input tokens on the configuration task.

| Task | Arm | Held-out | Input tokens | Uncached input | Output tokens | Time | Shell commands |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Ancestor script picker (#353) | Baseline | 1/1 | 368,185 | 28,601 | 4,589 | 124 s | 19 |
| Ancestor script picker (#353) | GAC | 1/1 | 602,050 | 58,434 | 5,667 | 176 s | 21 |
| Layered `.nirc` (#362) | Baseline | 3/3 | 636,854 | 36,662 | 7,248 | 191 s | 29 |

| **Two-task total** | **GAC** | **4/4** | **1,062,686** | **128,158** | **11,175** | **332 s** | **41** |

Compared with baseline, GAC used 5.7% more total input tokens, 96.4% more uncached input tokens, 5.6% fewer output tokens, and 5.4% more elapsed time across these two runs. The one-time memory-seeding pass stored 24 memories and used another 645,859 input and 4,902 output tokens; those costs are **not** in the table. The seed runner failed while closing its logs after the agent finished, so its elapsed time was not recorded reliably; the event trace and usage were preserved.

The untouched repository had 725 passing and four failing catalog tests, plus one typecheck error at `src/catalog/handler.ts:131`. Every task worktree retained those same four catalog failures and that same typecheck error. No new full-suite or typecheck failures were observed. The independent held-out checks fail on the untouched snapshot and pass on all four implementations. `git diff --check` passed for every worktree.

In both GAC attempts, the agent read the installed GAC skill and first called `recall` with `scope_id: capability:good-agent-context`. The external repo declares only `repository:ni-eval-2d8c88e`, so the server rejected that call. Each agent retried without a scope and successfully retrieved relevant memories. The skill's repository-specific capability advice is therefore a measured integration defect and a confounder for the treatment cost. The second GAC implementation did use fewer shell commands and less time, but this two-task sample cannot isolate whether memory caused that improvement.

Next experiment: remove the repo-specific capability advice from the generic skill, run the same paired protocol with randomized arm order and several attempts per task, and test a larger set of tasks across at least two repositories. Pre-register held-out checks and compare correctness first, then total and uncached tokens, time, and seeding amortization. Do not infer efficiency from agent-authored tests alone.

Raw per-run event, stderr, grade, and typecheck logs remain in `/private/tmp/gac-task-eval.3GI5Pk/*-artifacts/` on the evaluation host. The four solution worktrees are adjacent directories and were not committed or pushed.
